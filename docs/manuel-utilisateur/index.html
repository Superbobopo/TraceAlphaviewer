Pas à pas Captures expliquées 3 exercices

Vous n'avez jamais lu une trace Alpha ?

Ce guide part de zéro. Vous n'avez pas besoin de connaître Python ni les codes de la machine pour commencer. Les termes techniques sont expliqués au fur et à mesure.

Ce que fait le logiciel

Une trace est un fichier qui enregistre les messages d'une machine pendant son fonctionnement. TraceAlphaViewer transforme ces messages en une vue de la machine, des boîtes, des événements et des incidents.

Vous consultez un enregistrement : les boutons de lecture font avancer la trace affichée. Ils ne commandent pas la machine physique.

À propos des images. Les captures montrent les vrais écrans du logiciel avec des données fictives créées pour la formation. Le CIP 3400000000001, les produits « DEMO » et leurs incidents sont des exemples. Aucun fichier de trace terrain n'est fourni dans ce manuel.

Manuel correspondant à l'interface livrée après la correction du chargement réactif. Les volumes et les heures de vos traces seront différents.

01 • Prise en main

Votre première analyse en 5 minutes

Préparez un fichier de trace .old ou .txt enregistré sur votre ordinateur. Pour commencer, choisissez une trace courte si vous en avez une.

  1. Lancez le logiciel. L'écran d'accueil propose l'ouverture d'un fichier ou d'un dossier.
  2. Cliquez sur « Ouvrir une trace (.old/.txt) ». Choisissez le fichier et validez la fenêtre de sélection.
  3. Attendez l'affichage du viewer. L'accueil montre les étapes d'analyse. La trace brute, en bas du viewer, termine ensuite son chargement.
  4. Regardez « Diagnostic ». Lisez la synthèse globale, puis cliquez sur un incident dans la liste à droite pour en afficher le détail et rejoindre sa première ligne utile.
  5. Regardez ce qui se passe autour. Utilisez ◄ et ► pour avancer doucement. Retrouvez la boîte dans « References » si vous connaissez son CIP.
  • 1Le schéma montre l'état de la machine à l'instant sélectionné.
  • 2Les onglets regroupent les analyses et la recherche de références.
  • 3La barre de lecture sert à parcourir l'enregistrement.
  • 4La trace brute permet de lire les messages sources.
Résultat attendu : vous savez ouvrir une trace, sélectionner un incident et vous déplacer dans son contexte. Vous pouvez ensuite approfondir sans tout lire d'un coup.
02 • Démarrage

Lancer le logiciel

Double-cliquez sur TraceAlphaViewer.exe, reconnaissable à son logo « A » et convoyeur. Cette version fonctionne sans Python. Si vous utilisez le code source, lancez-le depuis le dossier du projet :

  1. Ouvrez le dossier TraceAlphaViewer qui contient le fichier README.md.
  2. Dans l'Explorateur Windows, cliquez dans la barre d'adresse, saisissez powershell, puis appuyez sur Entrée.
  3. Dans la fenêtre qui s'ouvre, tapez la commande suivante et validez :
python TraceAlphaViewer\Main.py

La fenêtre TraceAlpha Viewer apparaît. Laissez la fenêtre PowerShell ouverte pendant l'utilisation.

  • 1Une trace : pour étudier un fichier en détail.
  • 2Un dossier : pour consulter plusieurs traces et préparer un export CSV.
Si la commande ne fonctionne pas : vérifiez que vous êtes dans le dossier contenant le README. Si Python ou customtkinter manque, consultez l'annexe Installation ou demandez l'aide de la personne qui installe le logiciel.
03 • Chargement

Ouvrir une trace et attendre son analyse

  1. Cliquez sur Ouvrir une trace (.old/.txt).
  2. Sélectionnez le fichier. Les deux extensions sont acceptées ; le contenu doit être une trace Alpha.
  3. Validez, puis observez la progression. Le viewer apparaît lorsque les analyses et ses listes sont prêtes.

04 • Les repères

Comprendre l'écran

  • 1Bandeau : nom du fichier, nombre de frames, d'incidents et d'événements, heure courante, position dans la liste et ligne source.
  • 2Schéma : boîtes, capteurs et tapis à l'instant sélectionné.
  • 3Analyses : capteurs, diagnostics, références, erreurs et événements.
  • 4Lecture : commandes et curseur de position. La trace brute se trouve juste en dessous.

Trois nombres différents

RepèreÀ quoi il correspond
Heure, par exemple 09:00:48L'heure enregistrée dans la trace pour l'état sélectionné.
Frame, par exemple 25 / 31Le 25e état affichable parmi 31. Une frame est une photographie de l'état machine, pas nécessairement une seconde.
Ligne, par exemple L. 25Le numéro de ligne dans le fichier source. Une frame peut rassembler plusieurs lignes.

Agrandir les détails

Tirez la séparation horizontale située sous la barre de lecture pour donner plus ou moins de place à la trace brute. Masquer details la replie ; Afficher details la réaffiche. Agrandissez aussi la fenêtre si un tableau est trop étroit.

Le bouton Fermer du viewer vous ramène à l'accueil. La croix de la fenêtre Windows quitte l'application.

05 • Schéma machine

Lire le schéma et les couleurs

1Les points C0, C1… C9 représentent les capteurs. 2Les tapis portent leur nom T0 à T5. La zone EA se situe entre T2 et T3. 3Les petits rectangles avec un nom représentent les boîtes.

ÉlémentComment lire sa couleur
Point de capteurFoncé : inactif. Coloré : actif. Les couleurs diffèrent selon le capteur ; C4 peut être rouge, C5 vert, C6 orange et C9 bleu.
Flèche de tapisFoncée au repos, verte lors des codes actifs, rouge lorsque le code eT est négatif. Lisez son libellé : certaines valeurs négatives correspondent à une initialisation.
Fond d'un tapisReflète son état logiciel : repos, activité, disponibilité, initialisation ou erreur. Lisez également son code et son libellé dans Capteurs & Tapis.
Boîte sur T5Bleu clair : non évaluée. Vert : conforme (±3 mm). Orange : orientation différente. Hors tolérance : violet pour la longueur T4/C6, turquoise pour la largeur T5/C9, jaune pour la hauteur T5/LzB, rouge pour plusieurs dimensions. Rose : largeur invalide avec C9 actif. La légende reste en bas à droite ; survolez une boîte pour lire les valeurs et écarts.
Un point rouge ne signifie pas forcément une panne. Sur plusieurs capteurs, rouge signifie simplement « actif ». Interprétez la couleur avec l'emplacement, le moment du cycle et les messages.

Les positions et dimensions ne sont affichées que si la trace fournit les informations nécessaires. Le schéma aide à comprendre un cycle ; pour une valeur précise ou une identification, consultez les lignes sources et les références.

06 • États

Lire « Capteurs & Tapis »

  • 1Capteurs : état actif ou inactif à cet instant, avec leur emplacement.
  • 2Tapis : état logiciel, code eT et explication du code.
CapteurRepère de lecture
C0 / C1Entrée et sortie de T1.

Un état comme WAIT-COND indique une attente logicielle. Ce n'est pas à lui seul un diagnostic. Le même code numérique peut avoir un sens différent selon le tapis : utilisez le libellé de sa ligne. Par exemple, -1 peut désigner une initialisation.

Méthode simple : mettez la lecture en pause, regardez un capteur, puis avancez de quelques frames. Demandez-vous s'il change au moment où la boîte est censée passer devant lui.

Quelle commande utiliser ?

  • Pour voir le mouvement d'une boîte : lancez la lecture à vitesse réduite.
  • Pour lire un changement précis : mettez en pause et avancez frame par frame.
  • Pour une panne connue : cliquez sur l'incident ou utilisez les commandes d'erreur.
  • Pour une ligne ou un produit connu : utilisez la trace brute ou References.

Les commandes d'erreur rebouclent au début ou à la fin de la liste lorsqu'il n'y a plus d'erreur dans la direction choisie. Tous les diagnostics ne figurent pas dans cette liste : l'onglet Diagnostic reste le point d'entrée pour l'ensemble des incidents.

Raccourcis : Gauche/Droite, Espace, Début/Fin, e/Maj+e. Quand vous tapez dans un champ de recherche, ces touches servent à la saisie, pas au player.
08 • Produits et boîtes

Retrouver une boîte par CIP

Le CIP ou code-barres identifie un produit. Plusieurs boîtes du même produit peuvent donc partager ce code. L'onglet References garde des fiches distinctes pour les cycles de boîtes qu'il reconnaît.

  1. Cliquez sur References.
  2. Dans le champ CIP / filtre 1, saisissez un CIP, un code-barres, un nom ou un identifiant comme idB:102 ou IdA:202.
  3. Comparez les lignes proposées 2 : heure, ligne, parcours et identifiants.
  4. Cliquez sur la ligne de la boîte voulue. Le viewer rejoint sa première apparition connue. Entrée ouvre le premier résultat.
ColonneCe qu'elle vous apprend
Heure / LignePremière apparition de la fiche dans la trace.
ParcoursÉtapes observées, par exemple EA>T3>T4>T5>ROBOT. Une étape absente n'a pas été retrouvée pour ce cycle.
IdsidB identifie le cheminement avant T5 ; IdA identifie la boîte sur T5/BdD, notamment pour le robot.
Référence / nomLe produit identifié ou une référence provisoire comme ALPHA-INC-….
Ne choisissez pas uniquement par CIP. Si plusieurs résultats apparaissent, utilisez aussi l'heure et les identifiants. Deux lignes avec le même CIP ne sont pas nécessairement un doublon.

Pour voir tous les résultats à nouveau, effacez le champ. Si le bouton Unknown est activé, désactivez-le également.

09 • Lectures inconnues

Comprendre « Unknown » et « ALPHA-INC »

Lorsqu'une boîte n'est pas correctement identifiée, la trace peut contenir une référence comme ALPHA-INC, ALPHA-DET ou le mot unknow. Ces indications sont utiles pour chercher un problème de lecture caméra ou de DataMatrix.

  1. Dans References, effacez d'abord une recherche qui pourrait limiter les résultats.
  2. Cliquez sur Unknown 1. Le bouton change de couleur lorsqu'il est actif.
  3. Cliquez sur une fiche 2 et suivez son parcours. Regardez si CB2 a identifié le produit après une première lecture inconnue.
  4. Consultez ensuite le diagnostic global pour voir si les lectures inconnues forment un problème récurrent.

Une inconnue peut être relue ensuite

CB1 est la première zone de lecture. CB2 peut reconnaître plus tard une boîte qui était inconnue à son premier passage. Sa fiche peut alors montrer le vrai CIP tout en conservant l'ancienne référence comme origine.

Le filtre Unknown n'est pas un compteur d'inconnues finales. Il cherche les marqueurs présents dans les références, noms et origines. Le diagnostic UNKNOWN utilise les lectures finales et distingue notamment CB1+CB2, CB1 seul et CB2 seul.

Un diagnostic CAM-NO-READ concerne une caméra attendue qui n'a pas de réussite observée sur une trace suffisamment significative. C'est un indice à vérifier avec le contexte, pas une preuve automatique qu'elle doit être remplacée.

10 • Les messages sources

Chercher dans la trace brute

Le texte brut se trouve en bas de la fenêtre, sous la barre de lecture. Dans cette interface, il reste visible indépendamment des onglets d'analyse.

  1. Attendez la fin du chargement du texte.
  2. Saisissez un CIP, une heure comme 09:00:12 ou un fragment comme InitMachine dans CIP / texte 1.
  3. Attendez le nombre d'occurrences affiché à droite du champ. Les correspondances sont mises en évidence.
  4. Utilisez < et > à droite du champ, Entrée ou F3 pour passer à la correspondance suivante ; Maj+F3 pour la précédente.
  5. Le viewer rejoint l'état associé à la ligne trouvée. Vous pouvez aussi cliquer directement sur une ligne 2.

Reconnaître les surlignages

  • Bleu : ligne ou groupe de lignes de l'état sélectionné.
  • Jaune / doré : résultats de recherche et résultat courant.
  • L. suivi d'un nombre : numéro de ligne ajouté par le viewer ; ce préfixe n'est pas un message de la machine.

Le compteur de recherche affiche, par exemple, 1/8 : première correspondance sélectionnée parmi huit. La recherche ne tient pas compte des majuscules/minuscules et parcourt le texte disponible après son chargement.

Un CIP donne beaucoup de résultats ? Une même boîte apparaît souvent dans plusieurs messages. Utilisez References pour choisir son cycle, puis le texte brut pour lire le détail de ce passage.
11 • Vue d'ensemble

Lire le diagnostic global

Au chargement, l'onglet Diagnostic affiche une synthèse de toute la trace. Commencez par cette vue pour savoir quels problèmes examiner en priorité.

  • 1À gauche : synthèse regroupée par type de problème, avec priorités et exemples.
  • 2À droite : liste des incidents ; cliquez sur une occurrence ou un regroupement pour en lire le détail.
  • 3Vue globale : revenir à la synthèse après la sélection d'un incident.
NiveauLecture pratique
CRITIQUECommencez par ces incidents pour comprendre les erreurs ou blocages importants détectés.
ALERTEUn comportement mérite une vérification : mesure, identification, répétition ou attente inhabituelle.
INFOUne information de contexte utile, sans la même priorité d'analyse.
Tout le texte reste accessible. Les incidents à droite reviennent à la ligne. Déplacez le séparateur et utilisez les barres de défilement des deux panneaux. Un type peut regrouper plusieurs occurrences ; celles-ci ne correspondent pas toujours à des boîtes distinctes.
12 • Aller au détail

Examiner un incident

  1. Cliquez sur un incident dans la liste à droite du diagnostic.
  2. Le viewer rejoint sa première ligne utile ; le panneau gauche affiche son détail.
  3. Lisez le symptôme, la période, les causes possibles et les vérifications proposées.
  4. Examinez les lignes avant et après, avec le player et la trace brute.

1Contexte : code, confiance, lignes, période et nombre d'occurrences. 2Ce qui est observé : symptôme et résumé. 3Ce qu'il faut vérifier : causes probables et contrôles suggérés.

Mesures : le bilan distingue anomalies et toutes les mesures comparables : minimum, maximum, moyenne absolue et décalage signé (mesure − BdD). Une boîte compte une fois par cycle. Orientations, mesures invalides et données insuffisantes sont exclues et comptées à part. Un décalage régulier reste une piste à vérifier, pas une preuve de mauvais réglage. Les écarts firmware diffT4 sont distincts.
13 • Messages et cycles

Comprendre « Erreur » et « Evenements »

Erreur

Affiche les événements d'erreur, ainsi que les incidents T5 spécifiques ajoutés à cette navigation. Cliquez sur une ligne pour rejoindre le moment concerné.

Evenements

Affiche les événements, y compris les informations de transfert, d'identification et de robot. Les filtres T0 à T5 reconstruisent des séquences métier pour le tapis choisi.

Pour revenir à la liste complète, cliquez sur Tous. Sur une grosse trace, un filtre métier peut demander un calcul : le logiciel affiche un chargement pendant sa préparation.

Erreur et Diagnostic sont complémentaires. Erreur vous mène à des messages précis. Diagnostic regroupe et interprète des observations qui peuvent s'étendre sur plusieurs lignes ou ne pas être des messages d'erreur explicites.
14 • Partager votre analyse

Générer le rapport web et son PDF

  1. Dans Diagnostic, cliquez sur Rapport web.
  2. Attendez sa préparation. Le rapport s'ouvre dans le navigateur par défaut.
  3. Lisez les priorités et la synthèse, puis utilisez les filtres et groupes du rapport pour approfondir.
  4. Cliquez sur Exporter PDF dans le rapport pour télécharger sa synthèse globale.

Le bouton Exporter PDF crée un téléchargement direct : il n'ouvre pas la fenêtre d'impression. Retrouvez le PDF dans les téléchargements du navigateur, ou à l'emplacement qu'il vous propose.

Ouvrez une fiche pour lire constat, causes, contrôles et trois exemples représentatifs, puis tous les exemples par pages de 25. Recherchez un code, une référence ou une boîte. Le bilan des mesures reprend les chiffres du viewer.

Voir dans AlphaViewer rejoint la ligne de l'exemple dans la trace source encore ouverte et arrête la lecture. La liaison expire à sa fermeture ; le rapport reste consultable hors connexion. Les fichiers sont dans %LOCALAPPDATA%\TraceAlphaViewer\reports : conservez les annexes HTML, ou partagez le PDF.

Ce PDF n'est pas le manuel. Le PDF du rapport contient les résultats de votre trace. Le PDF « Bien démarrer avec TraceAlphaViewer » explique comment utiliser le logiciel.

  2. Sélectionnez le dossier contenant vos fichiers .old ou .txt.
  3. Attendez l'analyse, puis sélectionnez une trace dans la liste à gauche.
  4. Consultez ses onglets d'analyse et sa prévisualisation brute.
  • 1Choisir la trace à consulter.
  • 2Lire ses diagnostics, erreurs et événements.
  • 3Exporter le rapport du dossier en CSV.

Ouvrir le player d'une trace du dossier

Utilisez Ouvrir cette trace dans la synthèse ou Ouvrir la trace au-dessus de la prévisualisation. Un player séparé montre le schéma machine et permet de parcourir cette trace. La vue dossier reste disponible ; fermez le player pour la retrouver.

Exporter pour un tableur

Cliquez sur Exporter CSV, choisissez le nom et l'emplacement. L'export contient les diagnostics et les événements des traces du dossier, avec les fichiers, niveaux, lignes et heures. Il ne se limite pas à la trace sélectionnée.

Si le CSV s'affiche dans une seule colonne : utilisez l'import de texte/CSV du tableur, choisissez l'encodage UTF-8 et le séparateur virgule.
16 • À vous de jouer

Trois exercices guidés

Faites ces exercices sur une trace que vous avez le droit de consulter. Remplacez les valeurs fictives du guide par celles de votre fichier.

1 — Retrouver le passage d'une boîte

Point de départ : une trace ouverte et un CIP connu.

  1. Ouvrez References, effacez les anciens filtres et saisissez le CIP.
  2. Si plusieurs fiches apparaissent, comparez heure et identifiants.
  3. Cliquez sur la fiche voulue, puis avancez doucement dans la trace.
  4. Recherchez aussi ce CIP dans la trace brute pour lire ses messages.

Résultat attendu : vous pouvez noter un identifiant de cycle, une heure et une ligne source. Vous avez distingué un produit de chacune de ses boîtes.

2 — Examiner une erreur T4

Point de départ : une trace comportant une erreur ou un diagnostic T4.

  1. Dans Diagnostic, repérez le problème T4. S'il n'y en a pas, choisissez un autre incident présent dans la trace.
  2. Cliquez sur l'incident et lisez son détail.
  3. Consultez Capteurs & Tapis, notamment C6 si le diagnostic le mentionne.
  4. Regardez quelques frames avant et après, puis lisez les lignes sources.

Résultat attendu : vous séparez ce qui est observé de ce qui reste à vérifier. Par exemple : « trois demandes d'initialisation et C6 actif ; position ou signal C6 à contrôler ».

3 — Préparer un compte rendu

Point de départ : une trace analysée.

  1. Revenez à Vue globale et relevez les priorités.
  2. Ouvrez Rapport web, puis téléchargez son PDF avec Exporter PDF.
  3. Ouvrez le PDF et vérifiez qu'il correspond au rapport et à l'heure de génération.
  4. Si vous avez plusieurs traces, ouvrez leur dossier et exportez aussi le CSV.

Résultat attendu : vous disposez d'un rapport PDF et, si nécessaire, d'un tableau CSV. Ajoutez au partage le nom de la trace, la période étudiée et les observations que vous avez vérifiées.

Vous êtes autonome pour commencer : ouvrir, chercher, replacer un incident dans son contexte et transmettre une synthèse.

C0…C9Les repères des capteurs ; ils ne forment pas ici une série continue de tous les numéros.
CB1 / CB2Les zones de lecture du code de la boîte : CB1 côté EA, CB2 côté T3.
CIP / BarcodeCode d'identification du produit. Il peut être partagé par plusieurs boîtes.
idB / NboiteIdentifiant de cheminement d'une boîte avant T5.
IdA / id_alphaIdentifiant Alpha/BdD d'une boîte sur T5, utilisé notamment dans les messages robot.
BdDBase de données et informations de référence utilisées par Alpha.
eTCode firmware d'un tapis. Son libellé dépend du tapis concerné.
Unknown / ALPHA-INCMarqueur d'une identification inconnue ou provisoire ; la boîte peut parfois être relue ensuite.
ÉvénementMessage ou étape utile pour comprendre et parcourir un cycle.
Diagnostic / IncidentObservation interprétée ou regroupée, avec une période, des causes possibles et des contrôles proposés.
OccurrenceUne répétition comptée pour un incident ; pas forcément une boîte différente.
CubeStopVolet présent sur certaines machines entre EA et T3. Il apparaît si la trace indique son utilisation.
CSVFichier de tableau utilisable dans un tableur ; ici, séparé par des virgules et encodé en UTF-8.
19 • Dépannage de l'utilisation

Questions et problèmes courants

L'ouverture d'une grosse trace prend du temps

Regardez l'étape affichée sous la progression. Le logiciel lit et analyse toute la trace avec sa précision complète. La fenêtre peut être déplacée pendant ce travail. Le chargement n'utilise pas un cache de réouverture.

La recherche ne répond pas encore

Si le texte brut est en cours de chargement, attendez sa fin. La recherche affiche ensuite son nombre de résultats. Sur un long fichier, le décompte peut se compléter progressivement.

Le CIP n'apparaît pas dans References

Effacez les autres filtres et désactivez Unknown. Vérifiez le code, puis cherchez-le dans la trace brute. Une boîte peut ne pas avoir d'identité exploitable dans cette partie de la trace, ou porter une référence provisoire.

Le même CIP apparaît plusieurs fois

C'est normal si plusieurs boîtes ou cycles distincts portent ce produit. Comparez idB, IdA et l'heure de première apparition.

Le schéma ne montre aucune boîte à l'instant choisi

Essayez une autre frame ou rejoignez une référence connue. Il peut simplement ne pas y avoir de boîte suivie à cet instant, ou manquer des informations d'identification/position.

J'ai sélectionné un incident et perdu la vue globale

Cliquez sur Vue globale dans Diagnostic. La synthèse réapparaît.

Un capteur est rouge ; est-il en panne ?

Pas forcément : rouge est la couleur active de plusieurs capteurs. Observez son évolution pendant le passage d'une boîte et lisez les diagnostics associés.

Le rapport ne s'ouvre pas, ou le PDF est introuvable

Attendez la fin de sa préparation et regardez le message d'erreur éventuel. Vérifiez le navigateur par défaut, puis son dossier de téléchargements. Le rapport HTML local se trouve dans %LOCALAPPDATA%\TraceAlphaViewer\reports.

Le fichier est signalé en erreur de lecture

Vérifiez qu'il existe encore, que vous pouvez le lire et qu'il contient bien une trace Alpha. Une extension .txt ne suffit pas. En vue dossier, une erreur de lecture est affichée pour la trace concernée lorsqu'elle peut être isolée.

Une erreur de stockage temporaire apparaît

Vérifiez l'espace disque et l'accès en écriture au dossier du projet. Le chargement utilise un stockage de session sous TraceAlphaViewer\.trace_work. Les sessions gérées sont supprimées à la fermeture ; ne supprimez pas le dossier d'une trace encore ouverte.

Comment signaler un problème utilement ?

Notez le nom du fichier, l'heure, les lignes, le code du diagnostic, l'identifiant de la boîte et les actions effectuées. Indiquez ce que vous attendiez et ce que le logiciel a affiché. Une capture de la zone concernée aide à expliquer le problème.

20 • Annexe

Installation et partage du manuel

Cette annexe s'adresse à la personne qui prépare le logiciel sur le poste. Un utilisateur dont le logiciel fonctionne peut passer directement à la prise en main.

Préparer un poste Windows

Version exécutable : copier TraceAlphaViewer.exe sur le poste Windows 64 bits et le lancer par double-clic. Choisir ensuite les traces avec les boutons d'ouverture. Les étapes suivantes concernent la version Python.

  1. Installer Python 3.13 ou plus récent, avec Tkinter, fourni dans l'installation Python standard. Rendre la commande python accessible dans le terminal.
  2. Récupérer le projet et ouvrir PowerShell dans sa racine, où se trouve le README.
  3. Installer la dépendance graphique :
python -m pip install customtkinter

Lancer ensuite :

python TraceAlphaViewer\Main.py

Pour vérifier la version utilisée : python --version. Si Python n'est pas reconnu ou si ModuleNotFoundError: customtkinter apparaît, vérifier l'installation et exécuter l'installation de la dépendance avec le même Python que celui qui lance le viewer.

Distribuer ce guide

  • PDF : transmettre Bien-demarrer-avec-TraceAlphaViewer.pdf. Ce fichier est autonome et peut être imprimé.
  • Version web : transmettre tout le dossier manuel-utilisateur, avec index.html, le PDF et le sous-dossier assets. Ouvrir index.html dans le navigateur. Aucun serveur n'est nécessaire.
  • Après réception : ouvrir le guide, cliquer sur un chapitre et vérifier qu'une capture s'affiche. Aucun accès Internet n'est nécessaire pour consulter le manuel.

Maintenir les illustrations et le PDF

L'outil séparé utilise les vrais widgets avec des données fictives. Sous Windows, avec les dépendances du viewer, Pillow pour les captures et Edge (ou Chrome) installé :

python -m pip install pillow
python TraceAlphaViewer\Tools\generate_user_manual.py --captures --pdf

Après une modification de l'interface, vérifier les zones mises en évidence et les légendes dans le HTML, puis reconstruire le PDF. Les démonstrations et profils du navigateur sont temporaires ; aucun fichier de trace terrain n'est nécessaire.

Pour commencer maintenant : revenez à « Votre première analyse en 5 minutes », ouvrez votre trace et suivez les cinq étapes.
